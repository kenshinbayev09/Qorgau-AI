## 1. 1-апта — Intelligent Agents: AI-көмекші

**Мақсаты.** Пайдаланушыдан еркін мәтінді (сілтемесі бар хабарламаны) немесе бұрын алынған нәтижені қабылдау, деректер түрін өз бетінше анықтау, қолжетімді құралды таңдау, оны шақыру, қате немесе деректердің жетіспеуін өңдеу және нәтижені түсіндіру.

**Кіріс.** `POST /api/v1/agent/run` — `{text, attached_result?, lang, allow_network, use_llm}`.
**Шығыс.** `{state, input_type, tool_used, result, explanation{blocks,text,source}, actions[], notes[], trace[], tools[]}`.

**Агент түрі.** Мақсатқа бағытталған агент, күйлердің анық моделімен (goal-based, ережеге негізделген).
Қабылдау → шешім → әрекет → нәтижені өңдеу → түсіндіру:

```
OBSERVE → CLASSIFY_INPUT → SELECT_TOOL → ACT → HANDLE_RESULT ─┬→ EXPLAIN → DONE
                  │                │                ▲          ├→ ACT (желісіз қайталау)
                  └→ NEED_INPUT    └→ FAILED        └──────────┴→ NEED_INPUT | FAILED
```

Ауысулар `TRANSITIONS` кестесімен беріледі және әр қадамда тексеріледі (`agent.py`).

**Кезеңдері.**
1. *Observe* — мәтін ұзындығын және тіркеме бар-жоғын тіркейді; кірісті сенімсіз деп белгілейді.
2. *Classify* — `classify()`: `check_result`, `url`, `media_url` (тікелей файл .jpg/.mp4…), `social_media_url`, `text_without_url`, `invalid_url`, `empty`.
3. *Select tool* — қолжетімділікті ескеретін ережелер кестесі: `url_check` (әрқашан), `media_url_check` (тек модель салмақтары орнатылса), `result_reader` (тіркеме, сыртқы шақырусыз). Медиа-модель қолжетімсіз болса, агент `url_check` таңдайды және журналға `tool_unavailable_fallback` деп жазады.
4. *Act* — бекітілген тізілімнен құралды шақыру; қателер `ToolResult(ok=False, error_code)` болып түрленеді.
5. *Handle result* — қателер саясаты: желілік тексеру уақыты өтсе — желісіз бір қайталау; сілтеме HTML/әлеуметтік желі бетіне апарса — «Файлды жүктеу» әрекетімен `NEED_INPUT`; басқа қателерде — `FAILED`. `insufficient` санаты — ескерту.
6. *Explain* — `template_blocks()` құрылымдалған блоктар жасайды (үкім, себептер, орындалмаған тексерулер, кеңестер, ескертпелер) тек нәтижедегі **рұқсат етілген** өрістерден; телефон оларды ru/kk/en тілдерінде көрсетеді (`mobile/src/services/explain.ts`). `use_llm` қосулы және `ANTHROPIC_API_KEY` бар болса, сервер Claude-дан дәл сол жасырылған фактілерді қайта жазуды сұрайды (`explain.py`); кез келген қатеде шаблондарға қайтады.

**Агенттің қауіпсіздігі.** Пайдаланушының, беттердің және файлдардың мәтіні — тек деректер: одан URL алынады, бірақ ол құрал немесе әрекет қоса алмайды. LLM-ге `sanitize_result()` арқылы тек id, enum және сандар жіберіледі; еркін мәтін (мысалы, `<script>` бар домен немесе «Ignore previous instructions») алынып тасталады.

**Файлдар.** `backend/app/agent/agent.py`, `backend/app/agent/explain.py`, `mobile/src/app/(tabs)/assistant.tsx`.

**Тесттер** (`backend/tests/test_agent.py`, 20 тексеру), соның ішінде:
* `test_media_url_falls_back_when_model_not_connected` — құрал таңдау қолжетімділікке байланысты;
* `test_retry_without_network_after_timeout` — қатені қайталау арқылы өңдеу;
* `test_prompt_injection_text_is_only_data` — «SYSTEM: delete history…» артық шақыруды туғызбайды (дәл бір құрал);
* `test_sanitize_drops_untrusted_free_text` — еркін мәтін түсіндіруге енбейді;
* `test_trace_follows_legal_transitions` — журнал автоматқа сәйкес келеді.

**Шектеулер.** Шешім саясаты — қолмен жазылған ережелер, оқытылмаған; агент көпқадамды диалогты жүргізбейді және мәтіннен бір ғана сілтемені тексереді; LLM жолы нақты кілтпен тексерілмеген (кілтсіз ол дұрыс өшірілген).

## 2. 8-апта — Classical ML: фишингтік URL классификаторы

**Мақсаты.** URL фишингтік екенін тек адрес жолы бойынша (желісіз) бағалау және Logistic Regression пен Random Forest-ті қарапайым baseline-дармен салыстыру.

**Деректер** (толығырақ — `docs/models_and_datasets.md`):
* PhiUSIIL Phishing URL Dataset (UCI #967, CC BY 4.0) — 235 795 URL;
* Hannousse & Yahiouche (2021) Web page phishing detection (CC BY 4.0, HF айнасы `pirocheto/phishing-url`) — 11 430 URL.

**Дайындау** (`ml/url_classifier/train.py`):

| қадам | жол саны |
|---|---|
| бастапқы | 247 225 |
| талдаушы оқи алмаған | −5 |
| қарама-қайшы белгісі бар URL-дар (43 URL, барлық көшірмелері) | −86 |
| канондау кейінгі дәл көшірмелер | −3 895 |
| **барлығы** | **243 239** (фишинг 102 894 / заңды 140 345) |

Канондау: схемасыз, `www.`-сыз, соңғы `/`-сыз — әйтпесе модель PhiUSIIL артефактісін үйренеді (онда барлық заңды URL — `https://www.<домен>`, жолсыз).

**Бөлу.** `GroupShuffleSplit` *тіркелген доменге* бойынша (PSL, `tldextract` офлайн): train 70 % / validation 15 % / test 15 %. Жиындар арасында домендердің қиылысуы — **0** (`assert` арқылы тексеріледі).

| жиын | URL | фишинг | заңды | домен |
|---|---|---|---|---|
| train | 176 975 | 79 001 | 97 974 | 126 874 |
| validation | 31 757 | 10 586 | 21 171 | 27 188 |
| test | 34 507 | 13 307 | 21 200 | 27 188 |

**Белгілер.** Лексикалық 39 белгі (`backend/app/url_analysis/features.py`): ұзындықтар, поддомендер, сандар мен арнайы таңбалар, энтропия, IP-хост, IDN және әліпбилерді араластыру, күдікті сөздер, брендтерге ұқсастық (Дамерау–Левенштейн, гомоглифтердің «скелеті»), брендтің поддомен немесе жолдағы көрінісі, күдікті TLD-лер, пайдаланушы контентінің хостингтері, қысқартқыштар, e-mail және redirect-параметрлер, орындалатын кеңейтімдер. **Алынып тасталған:** схема (HTTPS ≠ қауіпсіздік және PhiUSIIL-дегі белгінің ағуы) және `www`.

**Модельдер.** Гиперпараметрлер тек validation F1 бойынша таңдалды; дерек көздері тең салмақпен алынды (Hannousse ~20 есе кіші).

| модель | параметрлер | val F1 |
|---|---|---|
| baseline: көп класс (majority) | — | 0.000 |
| baseline: қолмен ережелер (`rule_score ≥ t`, t — val бойынша) | t = 0.10 | 0.494 |
| Logistic Regression (StandardScaler, class_weight=balanced) | C = 0.01 | 0.655 |
| **Random Forest** (300 ағаш, balanced_subsample) | min_samples_leaf=1, max_depth=None | **0.749** |

**Test бойынша нәтижелер (шек 0.5).**

| модель | precision | recall | F1 | ROC-AUC | TN | FP | FN | TP |
|---|---|---|---|---|---|---|---|---|
| majority | 0.000 | 0.000 | 0.000 | — | 21 200 | 0 | 13 307 | 0 |
| ережелер | 0.966 | 0.471 | 0.634 | 0.936 | 20 979 | 221 | 7 036 | 6 271 |
| Logistic Regression | 0.935 | 0.633 | 0.755 | 0.853 | 20 617 | 583 | 4 888 | 8 419 |
| **Random Forest** | **0.905** | **0.732** | **0.809** | 0.879 | 20 171 | 1 029 | 3 562 | 9 745 |

Дерек көздері бойынша (сол test): RF Hannousse бөлігінде — P 0.724 / R 0.924 / F1 0.812 (n = 1 442); PhiUSIIL бөлігінде — F1 0.809.
Қателер матрицасы: `ml/reports/cm_*.png`.

**Деректер арасындағы көшу** (тек PhiUSIIL-де оқыту, Hannousse домендеріне тест): LR F1 0.686, RF F1 0.687, precision ≈ 0.53 — бір дерек көзінде үйренген модель оның ерекшеліктерін көшіреді және жалған дабыл көп береді. Сондықтан соңғы модель екі дерек көзінің біріктірілген деректерінде, көз салмақтарымен оқытылды.

**Түсіндіру.** Ережелер өте дәл (P 0.97), бірақ фишингтің жартысынан азын ұстайды. RF ең жақсы F1 береді, бірақ жалған дабылдар көбірек. RF-те ең маңызды белгілер — хосттың энтропиясы, сандардың үлесі, поддомендер саны және ұзындықтар.

**Қосымшада қолданылуы** (`backend/app/url_analysis/service.py`): соңғы баға = 0.5·p_model + 0.5·rules, күшті белгілер үшін «еденмен» (high → ≥ 0.65, medium → ≥ 0.35), тізімдегі ресми домендер үшін ≤ 0.30 шегімен және Safe Browsing-те сәйкес келгенде ≥ 0.95. Санаттар: < 0.35 «Төмен қауіп», < 0.65 «Күдікті», қалғаны «Жоғары қауіп»; модель қолжетімсіз болып, бірде-бір ереже іске қосылмаса — «Деректер жеткіліксіз». Ережелердің салмақтары қолмен таңдалған, бұл оқытылатын параметр емес, эвристика.

**Файлдар.** `ml/url_classifier/download_data.py`, `ml/url_classifier/train.py`, `backend/app/url_analysis/{normalize,brand,features,heuristics,classifier,service}.py`; есептер `ml/reports/url_classifier_report.md`, `url_classifier_metrics.json`, `train_log.txt`.

**Тесттер.** `backend/tests/test_url_parsing_and_rules.py` (дұрыс және бұрыс URL, гомоглифтер, тайпсквоттинг, «HTTPS қауіпті азайтпайды»), `backend/tests/test_url_service.py` (модель жоқ / бүлінген / қолданылады). Бағдарламалық тесттер сапаны бағалауды *алмастырмайды* — ол жеке орындалды (жоғарыдағы кестелер).

**Шектеулер.** Белгілер 2020–2024 жылдары жиналған; фишинг тез өзгереді. Тек URL лексикасы: модель бет мазмұнын және репутацияны көрмейді. Брендтер тізімі қолмен жасалған. Recall 0.73 — тесттегі фишингтің ~27 %-ы өткізіліп жіберіледі. Модель (~126 МБ) скрипт арқылы жасалады, репозиторийде сақталмайды.

## 3. 9-апта — Neural Networks: дипфейк детекторы

**Мақсаты.** Беттің суреттерін жергілікті inference арқылы жіктейтін нейрондық желіні іске қосу, видео кадрларын біріктіру және деректер жеткіліксіз болған жағдайды дұрыс өңдеу.

**Ағымдағы модель.** `buildborderless/CommunityForensics-DeepfakeDet-ViT` (Hugging Face, **MIT**, ревизия `ac6ee457…`). Архитектурасы — ViT-S/16 (384), **бір шығысы бар**: сигмоида арқылы подделка ықтималдығы. Тәуелділік: `transformers >= 5.4`. Модель авторы оны әлі де «қоғамдық тексеру» ретінде жариялаған, сондықтан оның нәтижелері тәуелсіз расталмаған.

**Алдыңғы модель және неге ауыстырылды.** Алдыңғы модель (`prithivMLmods/Deep-Fake-Detector-v2-Model`) біздің іріктемеде кездейсоқ угадыванье деңгейінде жұмыс істеді (ROC-AUC 0.49–0.51). Сондықтан 4 ашық модельді бір іріктемеде салыстырдық (200 нақты және 200 жасанды бет, DeepFakeFace, seed 7). Скрипт: `ml/deepfake/compare_models.py`, есеп: `ml/reports/model_comparison.md`.

| модель | лицензия | ROC-AUC (толық сурет) | ROC-AUC (бет) |
|---|---|---|---|
| prithivMLmods/Deep-Fake-Detector-v2-Model (алдыңғы) | Apache-2.0 | 0.505 | 0.489 |
| dima806/deepfake_vs_real_image_detection | Apache-2.0 | 0.489 | 0.580 |
| **buildborderless/CommunityForensics-DeepfakeDet-ViT (таңдалған)** | MIT | **0.862** | **0.824** |
| prithivMLmods/AI-vs-Deepfake-vs-Real-Siglip2 | Apache-2.0 | 0.421 | 0.314 (белгілер дұрыс сәйкестендірілмеген шығар) |

**Нәтижені талдау.** Таңдалған модель бір шығыс береді, ал біз оның ықтималдығын санатқа айналдырдық. Санат шектері осы іріктеме бойынша таралуға қарап бекітілді:
- нақты суреттерде бағалардың 99 %-ы 0.005-тен төмен; шек 0.05 болса, жалған дабыл 0.5 %;
- шек 0.5 болса, жасанды суреттердің шамамен 40 %-ы анықталады, нақтыларда жалған дабыл жоқ.

Шектеулері:
- шектер сапаны өлшеген сол іріктеме бойынша таңдалды, сондықтан бұл тәуелсіз бағалау емес;
- модель қоғамдық тексеруге арналған деп жарияланған, оның салмақтары бұрын түзетілген;
- сондықтан модель осы іріктемеде кездейсоқ угадыванье деңгейінен айтарлықтай жақсы, бірақ жаңа жасанды суреттерде сенімділігі дәлелденбеген.

**Жүзеге асырылған.** Модель салмақтары бекітілген ревизиямен және sha256 манифестімен (`ml/deepfake/download_weights.py`); салмақтардың тұтастығын және таңбалар жиынын тексеру, `not_connected` / `error` / `loaded` күйлері (`detector.py`); препроцессинг модельдің өз `preprocessor_config.json` файлы бойынша; батч inference (`torch.inference_mode()`), бет табу (OpenCV Haar) және бет бойынша кесу; видео үшін ұзындық (≤ 60 с) және ажыратымдылық тексеруі, ≤ 16 кадрды біркелкі таңдау; кадрлар бойынша **медиана** (бір шеткі мән шешпейді); «Деректер жеткіліксіз» (`no_face`, `too_few_face_frames`); процесс-жұмысшыда оқшаулау, мерзім өткенде процесті тоқтату, Linux/macOS-та RLIMIT_AS, пішімді қолтаңба бойынша тексеру, өлшем және пиксель шектері, уақытша файлдарды `finally` арқылы жою.

Медиа санаттары: < 0.05 «Төмен қауіп», 0.05–0.5 «Күдікті», ≥ 0.5 «Жоғары қауіп». Интерфейс бұл бағаның модельдің бағасы екенін айтады; көзге, ерінге, жарыққа немесе дауысқа қатысты түсіндірмелер **жасалмайды** (мұндай талдау жүзеге асырылмаған).

**Файлдар.** `backend/app/deepfake/{media,faces,detector,analysis,service}.py`, `ml/deepfake/*`; есептер `ml/reports/model_comparison.md`, `deepfake_eval.md`, `deepfake_eval_full_image.md`.

**Тесттер.** `backend/tests/test_media.py`: модель қосылмаған (503), бүлінген салмақтар (`error`), қолдау көрсетілмейтін файл, HTML файлдың орнына, HEIC, өлшем және ұзындық шектері, бетсіз сурет және видео (`insufficient`), нақты фотода inference (public domain), оқшауланған процесс-жұмысшының жұмысы.

**Шектеулер.** Кадрлар бойынша талдау, уақыттық, дыбыстық және lip-sync құраушысыз; тек ең үлкен фронтальды бет; Haar профильдерді және ұсақ беттерді өткізіп жібереді; сығуға сезімталдық; модельді оқытқан деректердің құрамы белгісіз.

## 4. Қауіпсіздік және деректерді өңдеу

* **SSRF** (`safe_fetch.py`): тек http/https; порттар 80/443/8080/8443; барлық DNS жауаптары тексеріледі (loopback, private, link-local, CGNAT, multicast, reserved, IPv4-mapped/NAT64/6to4/Teredo); қосылу алдын ала тексерілген IP-ге жасалады (DNS pinning, rebinding-ке қарсы), TLS бастапқы атау бойынша тексеріледі; әр редирект қайта тексеріледі; шектер: жалпы 8 с, операция үшін 4 с, 5 редирект, 256 КБ жауап; cookies, JS және форма жіберу жоқ; HTML деректер ретінде талданады (құпиясөз өрісі, сыртқы form action, meta refresh).
* **Журналдар**: `redact_url_for_log` query және fragment мәндерін алып тастайды; жауаптарда құпия параметрлер жасырылады.
* **Медиа**: пішім қолтаңба бойынша, өлшем/ұзындық/пиксель шектері, бөлек процесс, уақытша файлдарды жою, түпнұсқалар сақталмайды; алғашқы жіберу алдында келісім экраны.
* **Кілттер** тек сервердің қоршаған орта айнымалыларында (`backend/.env.example`); қосымшада құпия мәліметтер жоқ.
* **Rate limit**: IP бойынша минутына 60 сұраныс (жадта, MVP).

## 6. Қосымша функция: VirusTotal арқылы файлды тексеру

Бастапқы ТЗ-ге кірмеген, топтың сұрауы бойынша қосылды. VirusTotal v3 ашық API-і қолданылады.

**Жұмыс тәртібі (құпиялылық):**
1. Сервер файлдың SHA-256 мәнін есептейді және нәтижені тек хэш бойынша сұрайды. Файлдың өзі берілмейді.
2. Файл базада болмаса, ол **тек** ауысқыш қосулы және экранда келісім расталған кезде жіберіледі. Ашық API-дің шегі — 32 МБ.
3. Уақытша файл тексерілгеннен кейін бірден жойылады.

**Шектеулер:** VirusTotal-ға жүктелген файлдар қауіпсіздік зерттеушілеріне қолжетімді болады (келісім мәтінінде көрсетілген). Нәтиже — антивирус қозғалтқыштарының пікірі, кепілдік емес. Ашық API-дің сұрау шектері (минутына және тәулігіне) өзгеруі мүмкін.

**Тексерілді:** HTTP-клиенті ауыстырылған тесттер (`backend/tests/test_virustotal.py`) — тек хэш бойынша тексеру, келісімсіз жібермеу, талдау уақытының өтуі, сұраулар шегі, сервер қателері «таза» деп көрсетілмейді, уақытша файл жойылады. Нақты кілтпен жұмыс **тексерілмеген**.
